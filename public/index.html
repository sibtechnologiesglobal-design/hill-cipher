    // HOW IT WORKS

    01

    Password → Key Matrix

    Your password is hashed with SHA-256. The first four bytes of the digest seed a 2×2 matrix K. We force a and d odd and b even, so det(K) = ad − bc is always odd — and any odd number is coprime with 256, guaranteeing K is invertible.

    SHA-256(pw) → [a b; c d],  det ≡ 1 (mod 2)
    02

    Encrypt: C = K·P mod 256

    The image is decoded to raw R, G, B channels. Each channel is padded to even length and split into 2×1 pixel blocks. Every block is multiplied by K and reduced mod 256 — one linear transformation per pair of pixels, and the picture becomes statistical noise.

    [c₀; c₁] = K · [p₀; p₁] mod 256
    03

    Decrypt: P = K⁻¹·C mod 256

    Inversion uses the adjugate: K⁻¹ = det(K)⁻¹ · [d −b; −c a], where det(K)⁻¹ is the modular inverse found with the extended Euclidean algorithm. The same password rebuilds the exact same K — the wrong password builds a different matrix and yields pure noise.

    K⁻¹ = det⁻¹ · adj(K) mod 256
    04

    The .enc container

    Ciphertext travels in a tiny custom binary format — a 4-byte magic "ENC1", the image width, height and original format, then the encrypted channel data. Requests are processed entirely in memory; only the encrypted output and its metadata are archived — never your password, the key, or the original image.

    ENC1 | w:u32 | h:u32 | fmt | ciphertext
